### Backend-controlled reasoning budget (done; `feat/reasoning-budget`; plan: `docs/plans/reasoning-budget-control.md`)
Caps local reasoning models' hidden *thinking* tokens **per authoring operation** so triage finishes fast (the user's 10–20s/doc → ~Low) instead of the model over-thinking a 3-way classification. **Backend-only**, no frontend change, no user-facing toggle. Five phases, commit-per-phase, merged to `main`.
- **Phase 1 — vocabulary + detector:** `schemas/reasoning.py` (`ReasoningEffort` Low/Medium/High/VeryHigh/Max → 256/512/1024/2048/4096); `services/llm_backend.py` — probe `GET /version` (vLLM) / `GET /props` (llama.cpp), TTL cache keyed by base URL, `apply_reasoning` injects the engine-specific key (no-op for unknown). Config + `.env.example`: `LLM_BACKEND_POLL_SECONDS` (30) / `LLM_BACKEND_CACHE_TTL_SECONDS` (60).
- **Phase 2 — `chat_complete` wiring:** keyword-only `reasoning=` on `services/llm.chat_complete`; when set it detects the engine (cached) and adds `thinking_token_budget` (vLLM) / `thinking_budget_tokens` (llama.cpp); unchanged on OpenAI/unknown. Local import breaks the `llm ↔ llm_backend` cycle.
- **Phase 3 — per-call efforts:** `_common.DEFAULT_AUTHORING_EFFORT = Medium`; **triage = Low**; storyline/character/setting agents forward a `reasoning` param (default Medium); build runs blueprint + per-entity drafts at Medium. None of it user-controllable.
- **Phase 4 — poller + diagnostics:** lifespan `asyncio` poller re-probes the configured endpoint every `POLL_SECONDS` (adapts to engine swaps; cancelled on shutdown; skipped under SQLite); `GET /options/llm/backend` returns the detected engine + budget map (`LlmBackendResponse`).
- **Phase 5 — docs + validation + merge:** api-contract (Reasoning budget + endpoint), data-flow (Reasoning-Budget Flow), workflow/deployment/.env (env vars), documentation status; merged.
- **Validation:** 224 backend tests (ruff + mypy clean) — 10 new across detection, injection, per-call effort, the endpoint, and the poller. **Frontend untouched** (no run needed).
- **Decisions (from the user):** the budget ladder is Low 256 / Medium 512 / High 1024 / Very High 2048 / Max 4096; effort is **backend-set, not user-facing** for Storyline/Character/Setting creation; **Triage = Low**, **Build the whole world = Low/Medium** (Medium chosen for the generative calls); only **vLLM + llama.cpp** supported for now; auto-detect the engine and re-check periodically so the server adapts to changes.
- **Operator note:** the budget only takes effect when reasoning is enabled server-side — vLLM `--reasoning-parser <model>`; llama.cpp `--jinja --reasoning on` with **no** CLI `--reasoning-budget` (a CLI budget overrides the per-request one). An OpenAI / undetected endpoint behaves exactly as before (no key sent).
- **Deferred:** the vLLM native `reasoning_effort` enum (we use the numeric `thinking_token_budget` for exact, uniform control across all five levels); a "none" (fully-disabled-thinking) tier; surfacing the detected engine/budget in the Options UI (the diagnostic endpoint exists, but per "backend only" no UI was added).

### Build from attached docs only + ComfyUI down-guard (done; `fix/build-from-attached-docs`)
Two bug fixes to **Build the whole world**, from user reports.
- **(1) Cast/settings come ONLY from attached docs.** The build was inventing a cast/settings via the blueprint, ignoring the author's attached character/setting docs. Now: `BuildWorldRequest` carries `character_docs` / `setting_docs` (`BuildDoc{name,text}`); `build_agent.iter_build_world` creates **exactly one character per character-doc and one setting per setting-doc**, drafted from that doc, and **invents nothing** — no character docs → `characters == []` (likewise settings). The blueprint is now used only for the **stat schema** (its invented concepts are discarded). Attached docs alone are valid context (build with no seed/lore). The frontend (`useStorylineCreator.build()`) sends the docs categorized `character`/`setting`; the `plan` event's skeleton labels are the doc names.
- **(2) Stop hammering a down ComfyUI.** `imagesAvailable` only means a URL is *configured*; a stopped server 502'd on every entity. Now the build runs a **status preflight** (`checkComfyStatus`) before rendering and skips images entirely if unreachable, and both `renderProposalImages` (build) and `commitWorld` (commit) have a **circuit breaker** — the first failed render stops all further image calls (entities are still created, just without art).
- **Validation:** 202 backend tests (ruff + mypy clean; build tests rewritten for the no-invention behavior + per-doc cast) + 143 frontend tests (typecheck + lint + build clean; new tests for docs-as-cast, the circuit breaker, and the reachability skip).
- **Decisions (from the user):** the build must create **only** the attached characters/settings — never invent; if none are attached, none are created.
- **Follow-up — cast/settings are uncapped (`fix/uncap-attached-cast`, merged):** the old `MAX_CHARACTERS=6` / `MAX_SETTINGS=5` caps truncated large imports (a user attached 40+/50+ and got 6/5). Since the cast now comes only from attached docs (nothing invented), `_doc_sources` no longer caps — **every attached character/setting doc becomes an entity**. Only the invented stat schema stays bounded (`MAX_STATS=8`). (Practical limit is just time/cost — N sequential draft calls + N image renders.)
