# Mytheca — Component Map

Defines where frontend components live and who owns them. Ownership rules come from `docs/skills/repository-structure/SKILL.md`. Update this file as components are added.

## Layers

| Layer | Location | Contains |
| --- | --- | --- |
| Primitives (`ui`) | `web/frontend/components/ui/` | 23 reusable, domain-agnostic components — buttons, inputs, dialogs, chips, toasts. Hand-rolled; no Radix/shadcn dependency is installed. |
| Chrome (`layout`) | `web/frontend/components/layout/` | 6 components: `AppShell`, `AppHeader`, `SceneHeader`, `MotionProvider`, `ThemeSwitcher`, `ToastProvider`. |
| Domain (`feature`) | `web/frontend/components/feature/` | 55 Mytheca-specific components: narrator cards, character bubbles, rails, modals, panels, graph view. |
| Feature modules | `web/frontend/features/` | The four route-level modules that exist: `story-player/`, `library/`, `options/`, `documents/`. |
| Hooks | `web/frontend/hooks/` | Exactly four: `use-event-stream` (NDJSON consumer), `use-field-reveal`, `use-font-size`, `use-theme`. There is no `use-auth` — the app has no authentication. |
| Helpers | `web/frontend/lib/` | 14 files: API client, types, events, theme, fonts, graph colors, seals, card art, and formatting helpers. |
| Styles/tokens | `web/frontend/styles/themes.css` + `app/globals.css` | The three themes (Parchment/Ember/Slate) and their tokens, mapped to Tailwind utilities via `@theme inline`. `themes.css` is the only file in `styles/`. Decisions live in `design-system.md`. |

## Implemented (frontend)

| Component / module | Layer | Location |
| --- | --- | --- |
| `AppShell` | layout | `components/layout/AppShell.tsx` — themed page background/glow wrapper (server component); mounts `MotionProvider` + `ToastProvider` around the app. |
| `ToastProvider` / `Toast` / `useToast` | layout + ui | `components/layout/ToastProvider.tsx` + `components/ui/Toast.tsx` — app-global **top-right, stacking notifications** (portal). `useToast().notify({message, variant, title, durationMs, action?})` raises a toast; errors are `role="alert"`, info/success `role="status"`; an optional `action` renders one button (e.g. "Undo" for an auto scene-presence change) that fires its handler and dismisses. Framer `AnimatePresence` drives entrance, **exit**, and the `layout` reflow when a middle toast is removed, so the stack slides rather than jumps (portalled content sits outside the global CSS reduced-motion selector, so `MotionConfig reducedMotion="user"` is what covers it). Auto-dismiss shows a **draining countdown bar**, and **hover or focus pauses both the bar and the timer**, resuming with only the remaining time — an error worth reading must not vanish mid-read. Agentic-authoring errors across every surface raise an error toast. A no-op default context keeps isolated components safe without a provider. |
| `useHydrated` | hook | `hooks/use-hydrated.ts` — `false` during SSR and on the first client render, `true` afterwards. **Every `createPortal` in this app must gate on it.** A portal renders nothing on the server but inserts its container into `document.body` on the client, so rendering one on the first client pass leaves React reconciling a `<body>` child the server HTML does not contain — a hydration mismatch that regenerates the whole tree (and, as a knock-on, makes React re-create the root layout's init `<script>`s, which the browser then refuses to run). Built on `useSyncExternalStore`, matching `use-theme.tsx`, so there is no setState-in-effect. |
| `useExitTransition` | hook | `hooks/use-exit-transition.ts` — keeps an element mounted for one `--dur-fast` beat after it closes, so its **exit** has something to animate; returns `{mounted, closing}` for a `data-closing` attribute. React unmounts on the tick a conditional flips, which is why nothing in the app had an exit animation before. State is adjusted **during render**, not in an effect: `mounted` must be true on the same commit `open` becomes true, because callers focus into the element as they open it. Reduced motion unmounts immediately. Used by `Modal` and `MultiSelect`; the `.mytheca-menu` surface supplies the matching CSS. |
| `ProcessProgress` | feature | `components/feature/ProcessProgress.tsx` — compact **done/active/pending** stepper for an agentic run with a live `aria-live` "Now … · Next …" line. Used by `CharacterModal` (Identity → Voice & tone → Starting stats) and `SettingModal` (fields as steps). The storyline creator's build-stage steps were retired with "Build the whole world" — `StorylineCreatorView` no longer uses it. |
| `useFieldReveal` | hook | `hooks/use-field-reveal.ts` — choreographs a **field-by-field reveal** of an already-final result: `start(fields)` fills one field per ~150 ms tick, exposing `values`/`activeKey`/`done`; reduced-motion (or empty) reveals at once. `useLibraryState` uses the same pattern inline for the character/setting/scenario drafts (its earlier use for the retired world-build left-pane highlight was removed with "Build the whole world"). Paired with the `.mytheca-field-active` highlight utility in `styles/themes.css`. |
| `ThemeSwitcher` | layout | `components/layout/ThemeSwitcher.tsx` — three-dot Parchment/Ember/Slate picker. |

| Brand fonts | lib | `lib/fonts.ts` — Cinzel / EB Garamond / IBM Plex Mono via `next/font`. |
| UI primitives | ui | `components/ui/` — `Monogram` (initials avatar; optional `src` upgrades it to a portrait image with the same colored ring), `Eyebrow`, `SectionHeader`, `Tag`, `Chip`, `ToggleChip`, `IconButton`, `Button`, `FieldLabel`, `TextField`, `TextArea`, `Drawer` (the bottom sheet: portal, `useFocusTrap`, Esc/backdrop, body-scroll lock, `@starting-style` entrance with an explicit reduced-motion path; optional `externalClose` renders a reddish × hovering outside the panel, still inside the trap; optional `splitScroll` gives the panel's columns independent vertical scroll at `lg+` instead of the whole dialog scrolling), `FieldLabel` (bold + slightly larger for legible editor headers), `MultiSelect` (accessible single/multi dropdown — button trigger opens a `listbox` popover; `multiple` toggles checkbox-style multi-select vs single-choice replacement; outside-click + Esc close, roving focus over options with Arrow/Home/End + Enter/Space; `Monogram`/`◆`-seal row affordances; chip/name trigger display), `SceneControlSelect` (compact labeled dropdown — a mono micro-caption over a native `<select>` styled to the field tokens, `aria-label`led + keyboard-operable; **generic over `string | number`** with optional `{value, label}` options so an enum and a count can share one control, and `onChange` returns the ORIGINAL option value rather than the DOM's string — it used to coerce with `Number(...)`, which is why a string tier could not ride on it; optional `size`; used by `CastRail` and `TurnStatusStrip`). |
| Primitive interaction contract | ui | Every primitive carries all four states — `hover` / `focus-visible` / `:active` / `:disabled`. Hover effects that **move** an element go through `.hover-lift` / `.close-button-hover` in `styles/motion.css`, which gate them behind `@media (hover: hover) and (pointer: fine)`; un-gated, a touch device applies hover on tap and it sticks. Press feedback (`.press`) is never optional, because it is the only feedback that exists on touch. Hover rules on a control that can be disabled are scoped with Tailwind's `enabled:` so a dead control never lights up. Touch targets reach 44×44 on **coarse pointers only** — `.touch-target` where the control can grow, `.touch-target-overlay` (an invisible projected hit area, no layout effect) where it cannot, e.g. a 24px `IconButton` in a dense rail. |
| `Spinner` | ui | `components/ui/Spinner.tsx` — the one spinner in the app: a `currentColor` ring, `aria-hidden` (a spinner announces nothing useful; call sites pair it with real text or `aria-busy`). The ring is a static border with only the rotation animated, so reduced motion leaves a calm circle rather than an empty box. |
| `Button` loading variant | ui | `components/ui/Button.tsx` — `loading` swaps the label for a spinner **without changing the button's width**: the label stays in the DOM (merely `invisible`) holding the box open while the spinner is overlaid, so a control row never reflows the instant one is pressed. Sets `aria-busy`, disables the button, and takes `loadingLabel` for what it is doing ("Saving character") since the visible label is hidden. |
| `FieldError` | ui | `components/ui/FieldError.tsx` — inline validation message in a **reserved single-line box**, so an error appearing never pushes the next control down the form. `role="alert"` sits on the message, not the empty slot. `TextField`/`TextArea` render it only when an `error` prop is passed at all, so fields that never validate gain no extra height. |
| `useDelayedFlag` | hook | `hooks/use-delayed-flag.ts` — returns `false` for the first 300 ms of a wait, so a fast response shows **no indicator at all**. The highest-leverage single change in the loading ladder: it separates "the app is working" from "the app is flickering". Clearing happens during render, not in an effect, so the indicator is gone on the same commit the data arrives. |
| `Skeleton` family | ui | `components/ui/Skeleton.tsx` — `Skeleton` (the wrapper, which enforces a **deadline** and swaps in an error state rather than shimmering forever), plus `SkeletonLine` / `SkeletonText` / `SkeletonBlock`. Bars are `aria-hidden`; the container carries `aria-busy`. The last line of a text block runs 62% wide, because real prose does and uniform bars read as fake. The timeout depends on the *presence* of a timeout state, not the JSX node — depending on the node would restart the deadline every render and it would never fire. |
| `AsyncPanel` | ui | `components/ui/AsyncPanel.tsx` — the five-state shell (`idle · loading · success · error · empty`). Loading is gated by `useDelayedFlag`; error names what failed and carries a retry; empty carries its primary action inline; both enter with `.content-enter` like success. `empty` is deliberately not a flavour of `success` — collapsing them is how panels end up blank. |
| `SmartImage` | ui | `components/ui/SmartImage.tsx` — fades in on load, keeps a placeholder (monogram / "no art yet") mounted underneath, and treats a failed load as a state rather than a torn-page glyph. **Sizing is a discriminated union, and the choice is deliberate:** `aspect="16 / 9"` reserves space in normal flow (a standalone image), while `fill` makes the frame `absolute inset-0` for an image that is the **background of a box its parent already sizes** — every scenario/setting/character card, the carousel hero, the scene-loader backdrop. Callers must never pass positioning via `className`: `cn` is a plain string joiner, so a caller's `absolute` lands alongside the component's own `relative`, and Tailwind emits `.relative` last — so `relative` wins and a "background" image silently becomes an in-flow block above the text. Checks `img.complete` **in its ref callback**: a cached image never fires `load`, so a fade keyed only to `onLoad` leaves it permanently invisible. `priority` (eager + sync decode) is for the LCP image only — the carousel hero and the scene-loader backdrop. |
| `LibrarySkeletons` | feature | `components/feature/LibrarySkeletons.tsx` — column placeholders that **trace** the real cards: the scenario row's `min-h-[176px]`, the setting row's `min-h-[118px]`, and character tiles in the same container-driven `@[420px]:grid-cols-3` grid the real column uses. |
| `useStickyBottom` / `JumpToLatest` | hook + feature | `features/story-player/use-sticky-bottom.ts` + `components/feature/JumpToLatest.tsx` — the transcript follows new beats **only while the reader is already at the bottom** (64 px tolerance). ## Event → renderer mapping

Each of the 8 story-event types maps to exactly one renderer, all routed by `TranscriptBeat`:

| Event type | Renderer |
| --- | --- |
| `narration` | `NarratorCard` |
| `character_dialogue` | `CharacterMessage` (folds the character's `internal_thought` into the same bubble) |
| `character_action` | `CharacterMessage`, as an italic emote with no empty bubble |
| `internal_thought` | Rendered inside `CharacterMessage`, not as its own beat |
| `state_update` | `StateChips` in `DirectorRail`, plus the per-character stat rows in `CastRail` / `CharacterDossier` |
| `branch_choices` | `BranchChoices` — 1–2 stack in a column, 3–4 use a 2-column grid. Selecting one sends its text plus open-ended `guidance` |
| `character_status_change` | `CastRail` presence grouping, plus an Undo toast when the change was automatic |
| `cast_request` | `CastRequestBeat` — a centred card asking whether to bring an absent character in. **Never an arrival**: the AI has no way to introduce anyone, so this is a question with two answers and no default. Answering goes through the ordinary `setPresence` path (accept → `present`, decline → `departed` with `reason: "declined"`, which is what stops the ask recurring). Once answered it renders as a settled line and never as a live control again |
| `scene_image` | `SceneImageBeat` — centered landscape picture, clickable into `SceneImageModal` |

`useEventStream` (`hooks/use-event-stream.ts`) parses the NDJSON body of the turn **POST response** — not a separate `GET /stream` endpoint, which remains unbuilt.

## Conventions

- Each event `type` maps to exactly one renderer; the frontend never decides story layout beyond that mapping.
- Native HTML primitives first. No headless component library is installed — accessible behavior (focus traps, roving tabindex, listbox semantics) is hand-written in `components/ui/`.
- Streamed/updating regions (transcript, stats) use polite ARIA live regions and respect `prefers-reduced-motion`.
- Distinguish narrator / character / player / action visually **and** typographically — never by color alone (see `design-system.md`).
- FE↔BE types are hand-maintained in `lib/types.ts` and `lib/events.ts`, mirrored by hand against `web/backend/app/events/envelope.py`. **`web/shared/contracts/` is empty** — a reserved seam, not a live source. Keep the mirror in sync whenever the envelope changes.
