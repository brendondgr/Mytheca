# Mytheca — Route Map

The **eight** routes that exist in `web/frontend/app/`. There is no authentication, so no route is gated. Update this file whenever a route is added or removed.

## Frontend Routes

| Path | File | Purpose | Backend endpoints | States to design |
| --- | --- | --- | --- | --- |
| `/` | `app/page.tsx` | **The Library.** Header storyline switcher, recent-scenario carousel, and three open columns — Scenarios · Characters · Settings — side by side on desktop, collapsing to a tab switcher on mobile. Selecting a scenario features it, lights its cast, and brings its setting forward. With **zero** storylines it `router.replace`s to `/storylines/new`. | `GET /storylines` + per-storyline characters/settings/scenarios/stats; `POST`/`PATCH`/`DELETE` for each | loading, error (banner + Retry), empty, mobile |
| `/{storylineId}` | `app/[storylineId]/page.tsx` | **The Library, storyline-scoped** — the same surface, but the path id selects the active world on load (deep-linkable). Unknown ids and seed slugs (`embergate`) fall back to the first storyline. In-session switches rewrite the URL via `history.replaceState` without a remount. | same as `/` | same as `/` |
| `/{storylineId}/{scenarioId}` | `app/[storylineId]/[scenarioId]/page.tsx` | **Story player** — the core surface. `useSceneData` loads the real scenario, cast (+ portraits), setting (+ scene art), and stat schema, with an in-memory seed fallback if the scenario is unknown or the backend is unreachable. The transcript is **live and backend-streamed**: `useScenePlay` posts the turn and consumes the NDJSON event stream. Entering raises a scenario-aware establishing loader, then the chat with a `SceneIntro` band, portrait avatars, cast rail, and director rail. A header switch swaps the transcript for the **Graph view**; a single **☰ Scene** menu in the header holds **Writing…** (the scene's own prompt overrides, each value badged with the layer it comes from), the **Turn Inspector** toggle and **Export as Markdown / JSON**; and a header **Play-throughs** tray lists every saved play-through of the scenario — resume, rename, delete, or start a new one that leaves the existing story intact (the player no longer silently resumes `sessions[0]`). Every beat carries the same control cluster — **edit**, **re-roll** (beat or whole turn), **branch from here**, **rewind to here** — quiet until the beat is hovered or holds focus at `sm`+, plainly visible and 44px at the touch floor; a re-rolled beat gains a **take pager**. The composer's **Write it** control drafts the player's own line from a note about what they want it to do (persisted only if they send it), and the transcript's foot bar offers **Continue** — a turn with no player line at all — beside Create image. At the foot of the transcript, a **Create image** control paints the current moment (`POST /play/{id}/moment/stream`) and drops it in as a centered, clickable `scene_image` beat. | `GET /storylines/{id}/{scenarios,characters,settings,stats}`, `GET /storylines/{id}`, `POST /play/{scenarioId}/turn`, `POST /play/{scenarioId}/moment/stream`, `GET/POST/PATCH/DELETE /play/{scenarioId}/sessions…`, `POST …/sessions/{id}/{branch,rewind}`, `PATCH …/beats/{id}`, `POST …/beats/{id}/reroll`, `PATCH …/beats/{id}/take`, `POST …/ghostwrite/stream`, `POST /play/{id}/presence`, `GET /scenarios/{id}/graph` | loading (curtain), error (Try again + ‹ Library), streaming, reconnect, reduced-motion; **below `lg`: the `SceneRailBar` above the composer opens the cast, scene and scene-knowledge surfaces as bottom sheets** (one at a time, Escape closes, focus returns to the trigger; selecting a character raises the Scene sheet on their dossier) |
| `/play/{scenarioId}` | `app/play/[scenarioId]/page.tsx` | **Legacy redirect** → `/{storylineId}/{scenarioId}`, resolving the owning storyline (falls back to the first). Kept so old links don't break. | — | — |
| `/storylines/new` | `app/storylines/new/page.tsx` | **New Storyline page** — the creation surface and the empty-state default. Three columns at `lg+`: a left sidebar with the conversational scope-aware **Assistant** (chat → reviewable plan → approve fills the form); the by-hand fields in the center (title / genre / tagline / premise / World Primer / Statistics / seal); a right sidebar with the **Triage/Context** column and a context-budget meter. **Create World** first asks what to build (`BuildWorldModal`), then commits and — unless declined — generates and persists the world's cast + settings before redirecting to the populated Library. | `POST /storylines/triage/stream`, `POST /storylines/agent/create/stream`, `POST`/`PATCH /storylines`, `…/stats`, `…/context-docs/bulk`, `POST /storylines/{id}/populate/stream` | loading, error (alert), agent chat/plan/apply, triage progress, population progress, mobile |
| `/storylines/{id}/edit` | `app/storylines/[id]/edit/page.tsx` | **Edit Storyline** — the same `StorylineCreatorView`, prefilled from the world (its stats + context corpus). Saves by hand, or via the Assistant's converse → plan → approve loop, gated by the author's write scope and a server-side diff guard. | `GET /storylines/{id}` (+ stats + context-docs), `PATCH /storylines/{id}`, `…/stats`, `POST /storylines/{id}/agent/edit/stream`, `POST /storylines/{id}/agent/apply` | loading, error, success, mobile |
| `/storylines/{id}/documents` | `app/storylines/[id]/documents/page.tsx` | **Document manager** — the post-creation home for a world's context corpus. Lists every context document (storyline-level + entity-owned) with search, category filter, and group-by-bucket; each row edits usage (category + Draft/RAG/Extract), shows scope and provenance, views contents, or deletes. A drop zone uploads more. Reached from the storyline switcher's per-row **Documents** action. | `GET /storylines/{id}/context-docs` (+ entities for labels), `PATCH`/`DELETE /context-docs/{docId}`, `POST …/context-docs/bulk` | loading, error, empty, mobile |
| `/options` | `app/options/page.tsx` | **Options** — a centered panel with a vertical tab list. Tabs: **Language Models** (endpoint → fetch `/models` → pick model → params → connection test → `authoringConcurrency`), **Image Models** (ComfyUI base URL, workflow dropdown, defaults, status check), **Prompts** (global writing-agent prompt overrides), **Appearance** (theme), **Library defaults**, **About** (diagnostics, detected inference engine, reasoning-budget ladder, media-orphan maintenance). | `GET /options`, `PATCH /options/{llm,prompts,library,comfy}`, `POST /options/llm/{models,test}`, `GET /options/llm/{backend,context-window}`, `GET/POST /options/comfy/*`, `GET /options/media/orphans`, `POST /options/media/cleanup` | loading, error (banner + Retry), success, mobile (tabs collapse to a horizontal scroller) |

The root `app/layout.tsx` is the only layout. There are no route handlers (`route.ts`) anywhere.

## Not routes

Character, Setting, and Scenario editing all happen in **modals** launched from the Library — `CharacterModal`, `SettingModal`, and `EntityModal` + `ScenarioForm` respectively. There is no `/storylines/{id}/characters/{charId}`-style editor route, and no storyline "home" page at `/storylines/{id}` (only `/edit` and `/documents` exist under that segment).

There is also **no** `/sign-in`, `/sign-up`, `/library`, `/settings`, or `/admin/*` route. Earlier versions of this document listed them; none were ever built and none are scheduled.

## Backend routes consumed by the UI

Backend endpoints are catalogued in `api-contract.md`. Three RAG endpoints are worth naming here because they are consumed directly by the storyline editor rather than by a page of their own:

| Backend endpoint | Consumed by |
| --- | --- |
| `GET /api/storylines/{id}/rag/status` | Storyline editor footer — "✦ N embedded" count |
| `POST /api/storylines/{id}/rag/reindex/stream` | Storyline editor footer **Re-embed** button — streams live "Embedding i / N" progress |
| `POST /api/storylines/{id}/rag/query` | Debug only; not surfaced in the UI |

The API client (`lib/api.ts`) defaults `API_BASE` to `http://127.0.0.1:3345/api`, matching the backend's `/api` router mount.

## Notes

- **Storyline create/edit live on dedicated pages**, not a modal — the former `StorylineModal` was retired. The literal `storylines/` segment resolves before the dynamic `/{storylineId}` root (Next.js static-first).
- The **story player** is the only surface consuming the event stream. Its streaming and reconnect states are mandatory, not optional.
- Every page needs a unique, descriptive `<title>` and a logical heading hierarchy — see `skills/ada-compliance/SKILL.md`.
