## What can be said

**The baseline is not zero, and the plan was wrong to assume it would be.** With recall
switched off entirely, characters still reused an earlier turn's line verbatim in 1–2 beats
per scene (0.091, 0.125). A model handed a long transcript reuses material without any
memory layer. Had this been assumed rather than measured, every callback in the `on` arm
would have been miscredited to the feature.

**Recall fires reliably, and the cue channel carries all of it.** `recall_fire_rate` is 1.0
in both `on` runs — recall surfaced memories on every eligible turn — and `cue_share` is
**1.0** in both: every memory that reached a prompt had at least one subject-cue hit. The
subject channel added in Phase 5 is doing the work; on these scenes the participant channel
never had to act alone, and the semantic channel (Phase 6) never fired at all, because its
gate opens only when the cue scan finds nothing.

**The primary difference is not separable from noise at n=2.** `on` = 0.25, 0.125.
`off` = 0.125, 0.0909. The arms **touch at 0.125** — the `off` arm's best run and the `on`
arm's worst are identical. The same two runs per arm differ enormously in other respects
(the `off` arm produced 36 beats in one run and 14 in the other), which is the size of the
run-to-run variance this design is trying to see through. It cannot.

**The mechanism moves with the metric, which is the most interesting thing here.** Within
the `on` arm, the run offering more quotes produced more callbacks:

| run | quote offer share | callback rate |
| --- | --- | --- |
| on 1 | 0.80 | 0.25 |
| on 2 | 0.38 | 0.125 |

Two points are not a trend. But it is the relationship the design predicts — a quote cannot
be called back if none was offered — and it names the lever: **the scorer is blind to
whether a memory carries a quote.** `memory_recall.score` weighs salience, fade,
reinforcement, presence and cues, and never asks whether the memory has the thing that makes
a callback possible. A preference term is the obvious next change, and it is recorded in
`docs/checklist.md` as **evidence-suggested, not evidence-established**.

## What the failed run claimed, and what happened to it

`EXP-2026-09-001` found the `on` arm producing **12 character beats in both runs** against
23 and 31 — a large, consistent gap that nothing in the design predicted. **It did not
reproduce.** Here the `on` arm produced 41 and 37 beats and the `off` arm 36 and 14, so the
`on` arm is if anything the *longer* one. The anomaly is best read as an artifact of the
confounded run rather than an effect of recall, and it is retired rather than carried
forward.

## Limitations

- **n = 2 per arm.** The std in `manifest.yaml` is the spread of two points, not an estimate
  of a distribution. It is recorded because the schema requires it for `n > 1`, and it should
  not be read as an error bar.
- **One scenario, one cast, one set of directions.** Deliberately fixed to isolate the
  treatment; it also means nothing here generalises to other worlds or genres.
- **One model, at the app's default temperature (0.7).** Not a determinism study.
- **The metric is verbatim reuse of quoted speech, at 20 characters.** It cannot see a
  character alluding to a past moment in fresh words, which is a real and probably more
  common form of continuity. A high score means callbacks; a low score does **not** mean the
  memory had no effect.
- **`quote_verification_failure_rate` was not collected** — rejections are logged at DEBUG
  and not persisted, so how often the model composed an unusable quote is still unknown.
- No statistical test was run. With two runs per arm and overlapping ranges there is nothing
  a test would add that the rows do not already show.

## What would settle it

More runs per arm, on more than one world, is the whole of it — this design is sound and
under-powered, not wrong. A useful second step, given the mechanism table above, is a third
arm in which the scorer prefers memories carrying a verified quote: that turns "does memory
cause callbacks" into "does *offering a quote* cause callbacks", which is the narrower and
more answerable question.
