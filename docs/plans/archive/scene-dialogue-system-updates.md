# Scene Dialogue System — Updates (turn limit, follow-up suggestions, guided selection, deeper thinking, Composer controls)

## 1. Introduction

Five play-experience changes to the live scene turn loop, spanning the FastAPI turn engine/agents and the Next.js story player. Grounded in the **current** implementation (not the older `reactive-turn-director` plan doc, which is stale):

- **Turn loop** lives in `turn_engine.run_turn` — a `while beats < max_beats` ReAct loop where `planner_agent.next_beat` decides `speak` / `narrate` / `end`, and `max_beats = max(get_settings().turn_max_beats, 2*len(cast)+6)` is a global runaway backstop, **not** a per-scene feature cap.
- **Follow-up suggestions** are generated by `director_agent.propose_branches(db, ctx, turn_beats)` (2–4 `{label, outcome}` items, `_MAX_BRANCHES=4`) and emitted as a `branch_choices` event — but only behind `if needs_branch:`, and `needs_branch` comes from the planner's rarely-set `needsBranch` JSON flag, so **suggestions almost never appear** today.
- **Selecting a suggestion** currently calls `useScenePlay.choose → submit(c.player || c.label, c.outcome)`, sending the suggestion label **verbatim** as the player's message plus the `outcome` tag, which the backend "plays out over several beats" — i.e. it dictates rather than steers.
- **Character thinking** (`character_turn_agent`) runs at `ReasoningEffort.LOW` (256 thinking tokens) and the `_OUTPUT_CONTRACT` tells the character to keep `<thinking>` to "one or two clipped sentences," further shortened to "a few words" when a disposition is carried in — so characters emit a thin thought, not real deliberation.
- The **Composer** (`components/feature/Composer.tsx`) is a single flex row (input + Send); there are no per-scene controls next to it.

Locked product decisions (from the user): the two new controls are **persisted per-scene** (a `Scenario` field + migration); **"a turn" = character replies per player message** (bounds the `run_turn` beat loop; the planner may still end earlier); the **default follow-up count is 4**, rendered as a **2×2 grid** (range 0–4, `0` disables).

The approach: persist two per-scenario settings (`max_turns`, `suggestions_count`); bound the beat loop by `max_turns`; make suggestion emission count-driven and based on the **most recent dialogue turn only** (decoupled from `needs_branch`); reframe a selected suggestion as **open-ended guidance** injected into the prompts rather than a dictated script; deepen the character `<thinking>` step; and add two labeled dropdowns to the left of the Composer input wired to the persisted settings.

## 2. Gaps & Unanswered Questions

- **Persistence home — `Scenario` vs `PlaySession`?** (resolved, assumption): store on **`Scenario`** (`max_turns`, `suggestions_count`), so the controls are per-scene and survive reloads/return visits. The turn engine reads them from the scenario row; the frontend loads them with scene data and PATCHes on change. No `PlaySession` change.
- **Do the settings also ride in `TurnRequest`?** (resolved, assumption): **no** for `max_turns`/`suggestions_count` — the backend reads them from the scenario (single source of truth), avoiding a PATCH-then-turn ordering race. Only the new **guidance** signal for a selected suggestion rides in `TurnRequest`.
- **What does `max_turns` count?** (resolved): **character-speaking beats within one player-initiated `run_turn`** (narrator interstitials/puppet performances are not "turns"). The planner may still `end` earlier; when the character-speak count reaches `max_turns` the loop ends (hard ceiling, never exceeded). The existing `2*cast+6`/`turn_max_beats` runaway backstop is retained as a secondary guard.
- **"Most recent dialogue turn only" for suggestions?** (resolved): base `propose_branches` on the **last character dialogue beat** of the turn (fall back to the last non-empty beat), not the whole `turn_beats` transcript.
- **Deeper thinking — how much?** (resolved, assumption): raise `TURN_EFFORT` `LOW → MEDIUM` (256 → 512 thinking tokens) and rewrite the contract to ask for a **short in-voice paragraph (roughly 3–5 sentences)** of genuine deliberation in the character's own terminology; soften the disposition-shortening tail so it no longer clips to "a few words." Keep it private (`private_to_user`) and out of `turn_beats` (unchanged plumbing).
- **New UI select primitive?** (resolved, assumption): add a small reusable `SceneControlSelect` under `components/ui/` (labeled compact native `<select>` styled to the field tokens) — `MultiSelect` is too heavy for a numeric range. Reused by both dropdowns.
- **No complex gaps requiring human intervention.**

## 3. Hierarchical Step-by-Step Instructions

### Phase 1 — Backend: per-scene `max_turns` + `suggestions_count` (persist + bound the loop)

- **Locations:**
  - `web/backend/app/models/scenario.py` — add `max_turns: Mapped[int]` (default `5`) and `suggestions_count: Mapped[int]` (default `4`) columns (non-null, server defaults for existing rows).
  - `web/backend/alembic/versions/` — new migration adding the two columns with server defaults, chained on the current head.
  - `web/backend/app/schemas/scenario.py` — add `maxTurns` / `suggestionsCount` to `ScenarioBase`/`ScenarioRead`/`ScenarioUpdate` (clamp: `max_turns ≥ 1`, `0 ≤ suggestions_count ≤ 4`).
  - `web/backend/app/routes/scenarios.py` — ensure the scenario update route accepts and persists the two fields (add to the patch handler if not covered by a generic `model_dump`).
  - `web/backend/app/services/turn_engine.py` — in `run_turn`, read `scenario.max_turns`; track a **character-speak** counter in the loop; end the loop when it reaches `max_turns` (in addition to the planner's `end` and the runaway `max_beats` backstop). Emit a trace step when the cap is what ended the turn.
  - `web/backend/app/services/crud.py` — if scenario creation/serialization is centralized here, thread the two fields through defaults.
- **Rationale:** Persisted per-scene settings are the single source of truth the loop and suggestion stage both read; bounding the character-speak count is the direct fix for drawn-out exchanges.
- **Tests:** `utils/tests/backend/api/test_scenarios*.py` (create/read/update roundtrip of the two fields + clamp); `utils/tests/backend/api/test_play_turn.py` (a scenario with `max_turns=2` stops after 2 character beats even if the planner would continue; planner ending earlier is unaffected). Model default + migration smoke covered by the schema roundtrip.
- **Action:** Run `.venv/bin/python -m pytest utils/tests/backend/api/test_scenarios*.py utils/tests/backend/api/test_play_turn.py` + `ruff`/`mypy` on touched files. Once green, commit: `[Scene Dialogue Updates] (1/6) Complete: per-scene max_turns + suggestions_count persisted; loop bounded by character-reply cap.`

### Phase 2 — Backend: reliable, count-driven follow-up suggestions from the most recent turn

- **Locations:**
  - `web/backend/app/agents/director_agent.py` — `propose_branches` gains a `count: int` param (0 → return `[]` immediately; cap at `min(count, _MAX_BRANCHES)`), and builds its prompt from the **most recent character dialogue beat** (fallback: last non-empty beat) instead of the full `turn_beats`, so suggestions are direct follow-ups to what was just said.
  - `web/backend/app/services/turn_engine.py` — replace the `if needs_branch:` gate at end of turn with: read `scenario.suggestions_count`; if `> 0`, always call `propose_branches(..., count=suggestions_count)` and emit `branch_choices` when non-empty. Keep the `branch` trace step. `needs_branch`/`needsBranch` becomes advisory only (may still influence the trace text) — no longer the gate.
  - (No event-contract change: `branch_choices` / `BranchChoicesEvent` already carry a variable-length `choices` list.)
- **Rationale:** The feature "used to work but doesn't" because emission was gated on a flag the planner almost never sets; making it count-driven and anchored to the latest line restores reliable, relevant suggestions and honors the 0–4 range (0 disables).
- **Tests:** `utils/tests/backend/agents/test_director_agent.py` (count=0 → `[]`; count caps the list; prompt built from the most recent dialogue beat — assert via a recording fake LLM that the last line is in the prompt and older beats are not the anchor); `utils/tests/backend/api/test_play_turn.py` (suggestions emitted at end of turn when `suggestions_count>0` regardless of `needs_branch`; none emitted when `0`).
- **Action:** Run `.venv/bin/python -m pytest utils/tests/backend/agents/test_director_agent.py utils/tests/backend/api/test_play_turn.py` + `ruff`/`mypy` on touched files. Once green, commit: `[Scene Dialogue Updates] (2/6) Complete: count-driven follow-up suggestions from the most recent turn (decoupled from needs_branch).`

### Phase 3 — Backend: a selected suggestion steers open-endedly instead of dictating

- **Locations:**
  - `web/backend/app/schemas/play.py` — add `guidance: str | None = None` to `TurnRequest` (the open-ended steer carried when a suggestion is chosen). Keep `outcome` for backward compatibility but stop using it to "play out a script."
  - `web/backend/app/services/turn_engine.py` — when `guidance` is present, inject a **soft, open-ended directive** into the turn (a single framed line made available to the planner/character/narrator context) e.g. *"The story is being gently steered toward: «guidance». Move in this general direction while letting it unfold naturally — honor the intent, but produce original, unscripted dialogue; do not follow a rigid step-by-step script."* Replace/soften the current `outcome`-driven "progression narration played out over several beats" opening so a suggestion no longer dictates the beats.
  - `web/backend/app/agents/planner_agent.py` and/or `web/backend/app/agents/character_turn_agent.py` — accept the guidance directive in the prompt context (a MIDDLE/TAIL block) so both the next-beat decision and the character's voice bend toward the direction without scripting it.
  - `web/backend/app/agents/intent_agent.py` — ensure a guidance-originated turn is not mis-parsed as the player literally uttering the label (guidance is a direction, not a spoken line).
- **Rationale:** The user wants selection to *guide* not *dictate* — a general nudge that leaves room for an organic, unique outcome, while still honoring intent.
- **Tests:** `utils/tests/backend/api/test_play_turn.py` (a turn with `guidance` set injects the open-ended directive into the character/planner prompt via a recording fake LLM, and does NOT reproduce the guidance text verbatim as a dictated beat); `utils/tests/backend/agents/test_character_turn_agent.py` / `test_planner_agent.py` (guidance reaches the prompt as a soft steer).
- **Action:** Run `.venv/bin/python -m pytest utils/tests/backend/api/test_play_turn.py utils/tests/backend/agents/test_character_turn_agent.py utils/tests/backend/agents/test_planner_agent.py utils/tests/backend/agents/test_intent_agent.py` + `ruff`/`mypy` on touched files. Once green, commit: `[Scene Dialogue Updates] (3/6) Complete: selected suggestion becomes open-ended guidance, not a dictated script.`

### Phase 4 — Backend: deeper, in-voice character thinking before speaking

- **Locations:**
  - `web/backend/app/agents/character_turn_agent.py` — raise `TURN_EFFORT` from `ReasoningEffort.LOW` to `ReasoningEffort.MEDIUM` (256 → 512 thinking tokens). Rewrite the `_OUTPUT_CONTRACT` `<thinking>` instruction (the "SHORT thought … one or two clipped sentences" line and the "Lead with `<thinking>`: a brief … keep it clipped" line) to ask for a **short in-voice paragraph (~3–5 sentences)** where the character genuinely reasons through the situation in their own terminology/voice — still private, still not a narrator's clinical analysis. Soften the disposition-conditioned tail line ("You already know your stance — keep `<thinking>` to a few words.") so it invites the character to *expand* on their stance rather than clip it.
  - (No change needed to `emission.py` parsing or `turn_engine` emission — they already pass the full `<thinking>` text through as `private_to_user` with no cap.)
- **Rationale:** People deliberate through a paragraph before speaking; the current prompt + 256-token budget force a thin one-liner. More budget + a contract that asks for real in-voice reasoning produces the desired depth without leaking into shared dialogue.
- **Tests:** `utils/tests/backend/agents/test_character_turn_agent.py` (contract text asks for a fuller in-voice thought / no longer says "one or two clipped sentences"; `TURN_EFFORT == MEDIUM`; disposition tail no longer clips to "a few words"). Confirm `emission` thought-parse tests (`utils/tests/backend/services/test_emission.py`) still pass with a multi-sentence thought fixture.
- **Action:** Run `.venv/bin/python -m pytest utils/tests/backend/agents/test_character_turn_agent.py utils/tests/backend/services/test_emission.py` + `ruff`/`mypy` on touched files. Once green, commit: `[Scene Dialogue Updates] (4/6) Complete: deeper in-voice character thinking (MEDIUM effort + fuller <thinking> contract).`

Extend the props with the current values + change handlers. Keep the input + Send layout; ensure the row wraps/stays usable at 320–375px (stack or shrink controls).
  - `web/frontend/features/story-player/useScenePlay.ts` — hold `maxTurns`/`suggestionsCount` (initialized from the loaded scenario), expose setters that **PATCH the scenario** (persist) via `api`, and update `choose` so selecting a suggestion sends it as **guidance** (open-ended) rather than the label verbatim — send the suggestion text as the visible player input (consistent with current chat behavior) but carry it in the new `guidance` field of the turn body so the backend steers instead of dictating.
  - `web/frontend/features/story-player/StoryPlayerView.tsx` — thread the four new props into `<Composer>`.
  - `web/frontend/features/story-player/scene-data.ts` — surface `maxTurns`/`suggestionsCount` from the scenario payload.
  - `web/frontend/lib/types.ts` / `web/frontend/lib/events.ts` / `web/frontend/lib/api.ts` — add the two fields to the `Scenario` type, add `guidance` to `TurnRequestBody`, and add/confirm a scenario-PATCH client call.
